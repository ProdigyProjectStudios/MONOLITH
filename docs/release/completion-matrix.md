# Production V1 scope and completion matrix

The release covers one self-hosted installation with multiple authenticated organisations, one PostgreSQL database, Redis/RQ, an HTTPS gateway and a static Next.js client. Deterministic execution is the default. The portable Northstar showcase remains a separate deployment profile. A multi-region service, enterprise SSO and unattended monetary actions are outside V1. Each row starts from the inspected v5 source. Release results and operator dependencies are tracked in the acceptance report.

| Component | Evidence at audit | Gap or dependency | Acceptance criterion and method |
|---|---|---|---|
| Production entry | Private static Site v5; Compose FastAPI reachable on loopback | Hosted Site defaults to IndexedDB; no persistent Internet host or DNS supplied | Production client loads authenticated backend and preserves data on reopen; test same-origin gateway and verify on actual host |
| Identity and authority | Tenant bearer comparison and per-tenant SQL predicates | Shared tokens allow uploads and approvals by all users | Exercise named viewer, analyst, approver and admin; unauthenticated and foreign-tenant requests denied |
| Sources and content | CSV canonical IDs; bounded PDF page count; evidence page index | PDF parsing consumes API process resources; custom JSON ingestion absent | Limit request bytes and parser resources, validate content, replay identical event batch atomically, verify no cross-tenant observations |
| HubSpot | OAuth callback binding, encrypted tokens, checkpointed deal reads | Verify retries/cooldown, account binding and disconnect; external sandbox authorization needed | Controlled protocol tests plus independent real sandbox consent/sync/revoke gate |
| Graph and drift | Immutable revisions, process graph, half-open UTC windows, archived evidence endpoints | Distinguish source observations, inferences and synthetic streams; graph uses bounded samples | Baseline, backlog and recovery comparisons resolve to original source revision after restart |
| Workers and Studio | Six recorded stages, persisted events, resumable run, DB leases | Gap between SQL commit and queue dispatch; incompatible explicit AI/fallback behaviour | Interrupt after commit and stage; verify bounded recovery and unaltered provenance |
| Model and simulation | Real SDK transport and controlled provider; independent evidence checks and simulation assumptions | Explicit AI requests need cost/timeout enforcement across all execution paths; no funded acceptance authorization | Offline rejection, timeout, usage, veto, held disputes and replay tests; external model acceptance separate |
| API operations | Typed routes, health and privileged readiness diagnostics | Missing request limiting, paginated organisational data export, aggregate telemetry and readiness for orchestrators | Exercise limits, errors, readiness dependency failure, tenant-only export and operational signals |
| Lifecycle | Persistent evidence, audit and vector tables | Need audit retention, workspace erasure and backup handling with recovery safeguards | Safe scoped deletion/retention drills on disposable databases; preserve adjacent tenant; document backup expiry |
| Infrastructure | Docker Compose, persistent volumes, pgvector SQL migrations, Caddy TLS | Need staged rollout, image selection, rollback, validated backups, resource ceilings, scans and alerts | Deploy candidate, back up and restore into a clean target, test rollback and record load |
| Client and portfolio | Nine workspace views, 90s guided playback, traces, simulations, blueprint export | Keyboard, tablet, failure-state audit; missing explorer and technical case study | Operate each workspace, replay evidence through blueprint; automated accessibility and viewport tests |
| Release and external operations | Private Site, no confirmed public backend, paid calls disabled | Operator-controlled permanent host, DNS, sandbox consent and external alert delivery | Preserve v5 until a validated production replacement is available; report each unexecuted external gate |

The [release decision and gate results](readiness.md) link these criteria to the application, browser, security, recovery and staging receipts.
