Ingestion

Build around recoverable source records

The public Northstar input contains 1,706 event rows, five sources and one extracted policy page. CSV rows carry a case identifier, activity, timestamp and system. The import retains the source identity and row number. PDF evidence retains the page and excerpt. A reviewer can therefore return to both endpoints of a cited wait and inspect the policy governing the route.

Identifiers and timezones are normalised before analysis. An exact reimport is idempotent, and a conflicting external identity aborts the import. Feed omissions, inconsistent business identifiers and ambiguous event order remain limitations. The continuous detector excludes ambiguous adjacent transitions when events share a timestamp.

Process mining

Measure a transition with two witnesses

The refund report selects cases by final timestamp and retains their complete ordered traces. For each adjacent Invoice rekeyed → Refund authorised pair, it records elapsed hours and both event IDs. Sorting the measured intervals produces representative short, median and long examples. Multiple pairs in one case remain distinct intervals.

In the saved sample, 132 intervals span 132 cases. The interquartile range is 25.35–36.41 hours. The median of 31.15 hours describes elapsed wall time. Estimating operator labour from that number would count queue waiting as work and can double-count simultaneous cases.

System design

Freeze the input before specialists collaborate

In the API deployment, the request identifies a tenant and a case window. The service creates the run and saves its input snapshot before dispatch. A worker holds a lease and appends sequenced events. The client resumes its event stream after the last observed sequence. A repeat creates a separate run against the same frozen input so an engineer can distinguish model variability from a changed dataset.

Discovery establishes scope, process analysis measures intervals, strategy examines human controls, architecture proposes two routes, simulation prices the assumptions, and verification inspects the result. Each stage exchanges structured findings and evidence IDs. In the live SDK path, independent operations and reliability reviewers can disagree about the designs. Provider receipts supply model identity, tokens and elapsed duration when available.

The public browser demo runs the portable Python stages in a Web Worker and stores run inputs and receipts locally in IndexedDB. It exercises the investigation without a paid provider request. A deployed API uses server-side persistence. Browser evidence is specific to that browser profile. The deterministic case on this page establishes no live-provider acceptance result.

Counterfactual analysis

Compare routing alternatives on the same cohort

The event-driven queue creates a review item when a qualifying event arrives. The scheduled digest collects items between runs and incurs a polling delay. Both designs retain operator review and exclude disputed cases from routing. The historical replay can see the full trace. A pilot would need a point-in-time dispute check.

Saved scenario estimates in the synthetic 30-day run
Design Projected median Net savings
Review queue 22.34 h £336.78
Batch digest 26.55 h £275.89

The queue trial assumes 75% routing coverage, a 40% reduction on success, 4% routing failure, eight minutes of retained review and £40 per staff-hour. Failures can add delay and exception effort. The model combines success, fallback and uncovered paths at interval level, then calculates the projected distribution. A separate cost calculation includes manual and assisted effort, fixed and per-item costs.

Changing coverage or review effort can reverse a financial conclusion even when the projected median improves. A shadow pilot would need observed reviewer minutes, routing failures, coverage and handling costs to replace these assumptions.

Independent checks

Separate evidence coverage from factual support

The evaluator rebuilds expected measurements from the saved records and compares them with the submitted stages. It reports objective pass rates, finding-level citation coverage, unsupported assertions and human-control checks. The seed result passed 40 objective checks with zero failures, resolved eight of eight finding citations and still had two items requiring review. Causality and realised savings require independent measurements.

A failed independent check holds new approval. A passing verification leaves the design awaiting an operator. An actual approval records the chosen approach and time, and the dossier presents its implementation plan, contracts and dependencies. None of these steps sends money, writes to a CRM or deploys proposed architecture.

Continuous observation

Reassess the subject even after its alert clears

The continuous monitor compares adjacent seven-day windows and captures a historical graph. A supported change queues a deterministic six-checkpoint investigation. Each checkpoint binds the frozen source dataset, signal, relevant prior decisions and predecessor, allowing recovery without mixing evidence from different revisions.

In the public backlog and recovery streams, the same refund transition reached a 70.33-hour median and later measured 25.20 hours. These are seven-day, case-weighted observations with a different population from the 30-day investigation. The reassessment requires newer source witnesses and retains the original decision. Attributing the lower median to an implementation requires evidence of deployment and a comparison that accounts for case mix.

Verification route

Reproduce the case

  1. Open the Northstar synthetic demo, select the 30-day window and start a deterministic refund investigation in Intelligence Studio.
  2. Open the saved run's 90-second walkthrough. Inspect a source reference, compare both saved trials and inspect the blueprint preview.
  3. Open Observatory. Check the passed, failed and review counts against the frozen inputs. Repeat the deterministic run on the same snapshot to compare findings.
  4. In Continuous intelligence, load the labelled synthetic change and recovery streams. Compare saved revisions, checkpoint history and the later reassessment.
